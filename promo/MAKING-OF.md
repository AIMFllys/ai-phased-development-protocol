# 制作复盘：这支宣传片是怎么做出来的

这份文档按实际制作顺序，记录这支 30 秒「升维」宣传片的方法：叙事怎么定、节奏和卡点怎么控制、技术怎么搭，以及踩过的坑。最后一节是可以复用到下一支片子的清单。

---

## 一、先定故事和情绪，技术最后才考虑

1. **找一个贯穿全片的主角：Gate（闸门）。** 它就是这个 skill 的核心概念，从头到尾占着同一个屏幕位置，从铅笔稿一路变成金属发光体。画风怎么跳，观众都有锚点，不会迷路。
2. **让「升维」就是内容本身。** 五个 Phase 恰好对应五种画风：手绘 → 矢量 → 扁平 → 等距黏土 → 写实。画面每升一维，同时也在讲「每确认一步，东西就更真实」。形式和内容是同一件事，这是整个创意的核心。
3. **画出情绪曲线：** 温馨 → 不安 → 砸停 → 逐级上升 → 真空 → 爆发 → 回到温暖。每一段先定「观众此刻应该感觉到什么」，再决定画面和声音。
4. **高潮由人来触发。** drop 前一秒全黑，由人输入「确认 ↵」才引爆。产品理念（AI 等你点头）直接变成了最燃的一个节拍。
5. **首尾呼应。** 开头的钢琴动机在 drop 里变成主旋律，片尾又回到钢琴。片尾标题用手绘下划线，回到开头的纸面质感，从「燃」收回「暖」。

## 二、节奏：先搭节拍网格，再放内容

1. **120 BPM 是唯一的时间标准。** 1 拍 = 0.5 秒，30 秒 = 60 拍 = 15 小节。所有时间点只写在 `src/timeline.js` 一个文件里，画面、文字、音乐都从这里取。改一个时间点，全片会跟着一起动。
2. **每个 Phase 固定用一小节（4 拍）：**
   - 第 1 拍：转场重击（画风切换）。
   - 第 2–3 拍：内容按拍弹出（树节点、任务卡、执行令牌）。
   - 第 4 拍：确认「叮」，底部进度点点亮。

   重复的结构让观众形成预期：每小节末尾都会「确认」一次，下一拍一定升维。预期被一次次满足，就是节奏感的来源。
3. **密度曲线：**
   - 开头：笔画之间有停顿，一拍只发生一件事。
   - 混乱段：代码飞出的间隔按开平方分布，越来越密。镜头从每拍一切，最后加速到连续晃动。
   - 升维段：从八分音符的弹出，到十六分音符的镲。
   - drop：每 0.5 秒穿过一道门。
   - 蒙太奇：每 0.125 秒闪切一次，是全片最密的地方。
4. **留白是最重要的节拍。** 砸门之后冻结 0.2 秒再让混乱坠落；drop 前整整一秒近乎静音（-26 dB）。没有这两处「空」，后面的「满」就不燃。
5. **进入重击前先加速。** 闸门先缓慢垂下 0.3 秒，最后 0.1 秒猛砸（speed ramp）；高潮前有军鼓滚奏，从八分到十六分再到三十二分。观众的身体会先于画面预感到冲击。

## 三、技术核心：每一帧都是时间的纯函数

1. **状态完全由时间算出。** 整个画面由 `render(t)` 直接算出来，不依赖上一帧的状态。用无头浏览器逐帧设定 t 再截图，所以卡点精确到帧：不存在录屏掉帧，也不存在「动画实际跑得比预期慢」。
2. **这个设计带来的额外好处：**
   - 闪回蒙太奇几乎是免费的：26–27 秒只要把时间映射回 2.6s、6.55s、9.2s……重新渲染那些时刻即可。
   - 可以任意拖动预览、只渲染某一秒、多进程并行渲染。
   - 所有随机数都用固定种子，每次渲染结果完全一致。

## 四、音画同源：音乐从同一条时间轴生成

1. **音乐和画面是同一张时间表的两种输出。** 配乐不是做完画面再去对的，是用 `audio/make_music.py` 按同一条时间轴合成的。
   - 铅笔沙沙声：脚本直接解析 `paper.js` 源码里每一笔的开始时间和时长，画一笔响一声。
   - 故障点击音：用和画面同一个公式（`4.25 + 3.45·√(i/70)`）算出每行代码飞出的时间。
2. **每个视觉事件都配一个声音：**

   | 画面 | 声音 |
   |---|---|
   | 闸门砸下 | 低频冲击 + 金属声 + 镲 |
   | 勾选确认 | 铃声，每个 Phase 的铃音高一级（A5 → C6 → D6 → E6 → G6） |
   | 卡片滑入 | 呼啸声 + 落位声 |
   | 霓虹点亮 | 电流嗡声 |
   | 人按下回车 | 按键声 + 反向吸气音 |
   | 穿过每道门 | 从右到左的声像呼啸 |

3. **编曲跟着升维叠层。** Phase 2 只有底鼓和拨弦；Phase 3 加拍手；Phase 4 加踩镲；Phase 5 加锯齿和弦与滚奏。滤波器截止频率逐段打开（1600 → 2600 → 3800 → 6000 Hz），耳朵听到的「变亮」和眼睛看到的「升维」同步。
4. **响度曲线是量出来的。** 第一版各段响度差不多，Act I 几乎和 drop 一样响。改法是加分段增益自动化，再用逐段 RMS 和频谱图验证。结果：开场 -20 dB → 混乱 -14 → 砸门峰值 → 握手 -17 → 构建 -11 → 静默 -26 → drop -8。另外对 drop 做了侧链压缩，让合成器跟着底鼓「呼吸」，律动感来自这里。

## 五、视觉系统：每个时代一套完整设计语言

1. **色彩叙事是「从傍晚到深夜」：** 暖纸色 → 白色蓝图 → 藏青海报 → 黄昏黏土 → 深夜科技。台灯的琥珀色贯穿到底，最后成了传送门的颜色。温暖没有消失，而是升级了。
2. **字体也跟着升维：** 霞鹜文楷手写体 → JetBrains Mono 等宽 → Space Grotesk 加思源黑体 Black → 科技 HUD。左上角的 Phase 标签每个时代换一种排版风格。
3. **手绘引擎是自己写的（`src/lib/sketch.js`），没有用现成库：**
   - 笔触用带压感的填充轮廓，两端收笔变细。
   - 沿法线加分形噪声，模拟手的抖动。
   - 每秒 12 次重新随机（line boil），模拟逐帧手绘动画的「线条在呼吸」。
   - 混乱段把抖动幅度乘到 3.4 倍、沸腾频率翻倍，线条本身就在焦虑。
4. **每个转场都是一种「变形」，不是硬切：**

   | 转场 | 做法 |
   |---|---|
   | 手绘 → 矢量 | 抖动幅度用 outBack 缓动归零，线条「啪」地拉直 |
   | 矢量 → 扁平 | 闸门从下往上填色，再用圆形转场（iris）打开新世界 |
   | 扁平 → 黏土 | Phase 3 的扁平画面其实已经是 3D 场景，只是用 0.6° 视角假装正交、且与 2D 画面像素对齐。镜头一转，厚度长出来 |
   | 黏土 → 写实 | 视角从 0.6° 推到 40°，同时保持主体大小不变（希区柯克变焦），材质同时从黏土变成金属和玻璃 |
   | 写实 → 高潮 | 推进传送门 → 全黑 → 人确认 → 白闪爆发 |

## 六、用到的剪辑手法

| 手法 | 用在哪 |
|---|---|
| 硬切推近（smash cut） | 混乱段 5.0 / 5.5 / 6.0 / 7.0 秒，每拍切到一个红笔批注特写 |
| 变速（speed ramp） | 闸门下落；穿过第 5 道门后的慢动作 |
| 冲击帧 | 砸门反色 2 帧；STOP / CONFIRM / SHIP 各反色 1 帧 + 白闪 |
| 衰减震屏 | 指数衰减的噪声位移，每次重击的强度不同 |
| 冻结后坠落 | 砸门后，混乱的代码定格 0.2 秒，再受重力掉出画面 |
| 遮幅（letterbox） | 从静默开始收成宽银幕，告诉观众「正片开始」 |
| 动态文字 | 砸字：1.5 倍缩放 → 1，模糊 14px → 0，红青色差分离逐渐衰减 |
| 闪回蒙太奇 | 8 个十六分音符闪切回顾所有时代 |
| 甩镜揭示 | 慢动作之后猛拉远，看到整条状态机 |

**缓动的使用规则：**

- 冲击用 outExpo（瞬间到位、慢慢停稳）。
- 弹出和吸附用 outBack（带一点回弹）。
- 砸下用 inQuad / inExpo（越来越快）。
- 运镜用 inOutCubic。

按照功能固定选哪种缓动，全片动作的手感才一致。

## 七、工作流：静帧驱动的快速迭代

1. **流程：** 先写完整分镜，再搭引擎，然后每段渲几张静帧拼成接触表（contact sheet）来看。看到问题就定位、修复、重渲，一段一段往前推。
2. **这个流程抓到的真实问题：**

   | 现象 | 根因 | 修法 |
   |---|---|---|
   | 画面缺一大块 | 全屏 SVG 遮罩超出 Chromium 的光栅瓦片预算 | 改用 CSS clip-path |
   | 3D 画面出现黑色巨块 | 补光灯太强，HDR 缓冲溢出成 NaN，辉光模糊把它扩散开 | 降低灯光强度 + 在着色器里钳制数值 |
   | 震屏时画面转了 40° | 旋转量把弧度当角度又乘了 57 | 修正单位 |
   | 闸门下落看不见 | inExpo 太陡，门在画外待到最后两帧 | 改成「先缓慢垂下，再猛砸」 |
   | 地板发灰 | 半透明地板吃到高光 | 改成不受光的黑色釉面 |
   | 字体没加载 | 按 Unicode 分片的字体只加载了中文样本，英文分片没触发 | 预加载时加入英文样本 |

3. **诊断手段：** 逐个隐藏对象、读中心像素定位是哪个物体出问题（`render/probe.mjs`），打印相机参数，画音频的 RMS 曲线和频谱图。原则是用数据判断，不靠猜。

## 八、已知的不足与后续

1. **配乐是合成的。** 换一首真实的 120 BPM 曲目（drop 放在第 19 秒）提升最大，做法见 `README.md`。
2. **成片文件偏大。** 颗粒噪点会显著推高码率（30fps 预览在 CRF 14 下约 465 MB）。发布前建议给编码器设目标码率（例如 `-b:v 12M`），或者降低 `fx.js` 里的颗粒强度。
3. **还没做运动模糊。** 穿门和甩镜这类高速镜头加上运动模糊会更有电影感：可以每帧渲染多个子帧再平均。
4. **云端没有 GPU，渲染慢。** 正式的 60fps 版本建议在本地用显卡渲染（`npm run render:gpu`）。

## 九、可以复用的方法清单

1. 用一句话讲清楚：主角是什么，情绪曲线怎么走。
2. 让形式本身承载内容（这次是「升维 = Phase」）。
3. 先定 BPM 和节拍网格，把所有时间点集中写在一个文件里。
4. 每个段落用固定的节拍模式：重击 → 弹出 → 确认，让观众形成预期。
5. 设计密度曲线，而且一定要留出真空。
6. 画面写成时间的纯函数，逐帧渲染。
7. 音乐和画面从同一条时间轴生成，每个视觉事件都配一个声音。
8. 转场优先做变形，其次才是硬切。
9. 按功能固定缓动类型，保证动作手感一致。
10. 用静帧接触表迭代，用数据诊断问题，用 RMS 和频谱检查响度。
