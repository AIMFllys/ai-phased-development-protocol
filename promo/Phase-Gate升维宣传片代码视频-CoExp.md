# 一、创作思路

## 1. 需求怎么拆成叙事结构

### 1.1 原始需求（按对话顺序）

1. 「世界上最牛的代码视频，手绘 SVG 风格，从温馨到激昂」
2. 「后期像升维一样，从手绘逐渐过渡到写实、科技风，顶级设计和卡点，30 秒左右，动作丰富，结合顶尖剪辑手法」
3. 「横屏，正式开始」

### 1.2 拆解步骤

**第一步：找到内容本身和形式之间的对应关系。** 视频宣传的是一个 Phase-Gate（阶段闸门）状态机 skill，它有 5 个 Phase。用户要求画风「升维」。于是做了一个关键决定：

> **5 个 Phase = 5 次升维。** 每过一道 Gate，画面就升一个维度：手绘 → 矢量 → 扁平 → 等距 2.5D → 写实 3D。

这样升维本身就是在讲产品：「每确认一步，东西就变得更真实」。观众不需要看懂 Phase-Gate，也能「感觉到」它。

**第二步：定一个贯穿全片的视觉锚点。** Gate 闸门是一个 Π 形门框（外框 320×420，门柱和门楣各宽 44px）。它在屏幕上的位置从头到尾不变（x 800–1120，y 360–780），画风怎么跳，观众都有锚点，不会迷路。

**第三步：画情绪曲线，再把曲线落到节拍网格上。** 定了 120 BPM（1 拍 = 0.5s，1 小节 = 2s），30 秒 = 60 拍 = 15 小节。

| 时间 | 小节 | 情绪 | 段落 | 情绪强度（主观 0–10） |
|---|---|---|---|---|
| 0–4s | 1–2 | 温馨 | Act I 深夜书桌 | 2 |
| 4–8s | 3–4 | 不安 → 窒息 | Act II AI 失控 | 3 → 7 |
| 8–10s | 5 | 砸停 → 喘息 | Act III Gate 1（手绘） | 8 → 3 |
| 10–12s | 6 | 秩序 | Phase 2（矢量） | 4 |
| 12–14s | 7 | 明快 | Phase 3（扁平） | 5 |
| 14–16s | 8 | 成型 | Phase 4（等距黏土） | 6 |
| 16–18s | 9 | 蓄力 | Phase 5（写实 3D） | 7 → 8 |
| 18–19s | 半小节 | 真空 | Act V 人类确认 | 1 |
| 19–22s | 10–11 | 爆发 | Act VI 穿门 | 10 |
| 22–26s | 11–13 | 宏大 | 揭示 + STOP/CONFIRM/SHIP | 9 |
| 26–27s | 14 | 回顾 | 1/16 音符闪切 | 9 |
| 27–30s | 14–15 | 回温 | 标题 | 5 → 3 |

**第四步：把「产品卖点」变成「最燃的节拍」。** skill 的核心是「AI 停下来等你确认」，于是高潮前的一秒全黑，由人输入「确认 ↵」才引爆 drop。产品理念 = 剧情转折 = 音乐 drop，三者合一。

**第五步：首尾呼应。** 开场钢琴动机（A4 C5 E5 F5 E5 D5）在 drop 里变成锯齿波主旋律，片尾又回到钢琴。片尾标题下面有一条手绘沸腾的琥珀色下划线，把「燃」收回「暖」。

### 1.3 规划阶段对用户说清楚的三个风险

在开工前的分析里就明确说了，后来都应验了：

1. **「写实」的上限**：代码渲染能做到「精致 3D 材质感」，做不到照片级真人真景。后来就把「写实」定义为金属、玻璃、霓虹加镜面地板。
2. **卡点依赖音乐**：先有节拍网格，再放画面。
3. **最难的是 Phase 4→5 的 2D→3D 衔接**：后来用「Phase 3 其实已经是 3D、只是视角 0.6° 假装正交」解决了。

## 2. 每个段落的设计意图

### Act I · 温馨（0–4s）

- **画面**：米黄纸面上，铅笔一笔笔画出书桌线、笔记本电脑、台灯、马克杯、窗户（月亮和星星）、盆栽、便利贴。之后水彩晕染上色，台灯投出暖光锥。便利贴上手写「今晚，写点什么吧 ✎」，屏幕里打字「> 帮我做一个登录页」，AI 回复「好的！马上开始 ✓」。
- **为什么**：
  - 一根铅笔跟着正在画的线条尖端走：让观众看到「正在被画」，而不是静态插画。
  - 每条线大约 0.1–0.6 秒，节奏舒缓，一拍只发生一件事。
  - 镜头 4 秒内从 1.00 缓慢推到 1.10：温馨段唯一的运动，很克制。
  - 台灯的琥珀色是全片的「灵魂色」，后面会一路保留到传送门。
- **小伏笔**：AI 回复的第三行已经是 `import * as all from "./all"`，第五行是 `// 重写全部…`。

### Act II · 失控（4–8s）

- **画面**：70 行代码从屏幕飞出，铺满纸面。4 条「主角代码」被红笔圈出并批注：
  - `rewriteEverything();` → 重写了整个项目？！
  - `export default MegaComponent` → main.js · 2,847 行
  - `if (bug) fixBug() && addTwoMore()` → 修 1 个 Bug → 冒出 3 个
  - `rm -rf ./architecture` → 我的架构呢…？

  6.5s 红色大叉划掉屏幕；6.95s 起 18 条愤怒的圈状涂鸦淹没画面；7.45s 起画面压暗。
- **为什么**：
  - 这些批注就是 README 里列出的痛点（一口气几百行、重写、Bug 越修越多、架构失控），把文字需求变成了可视的「罪证」。
  - 手绘线条的抖动幅度从 1 倍线性加到 3.4 倍，沸腾频率从 12fps 翻到 24fps：线条本身在焦虑。
  - 台灯开始闪烁，马克杯的热气变成锯齿。

### Act III · Gate 1 手绘（8–10s）

- **画面**：
  - 手绘 GATE 先从画面上方缓慢垂下（7.6–7.9s），再猛砸下来（7.9–8.0s）。
  - 8.0s 冲击：反色 2 帧 + 白闪 + 34px 衰减震屏 + 墨迹飞溅 + 门柱底部扬尘。
  - 所有飞舞的代码冻结 0.2 秒，然后受重力掉出画面。
  - 左边出现需求清单（打勾），右边是握手气泡「✅ Phase 1 已完成。请确认后，我再进入 Phase 2。」。
  - 9.5s 勾选「确认」，红白栏杆用 outBack 抬起。
- **为什么**：先让观众经历失控，再给出「停下」，Gate 的价值不用解释。握手问句是 SKILL.md 里的原话，是真实的产品界面。

### Phase 2 · 矢量（10–12s）

- **画面**：
  - 抖动的手绘线条在 0.32 秒内「啪」地拉直（抖动幅度 → 0，缓动用 outBack 带回弹），颜色从石墨色变成墨蓝 `#1F2A44`。
  - 纸面变白，出现点阵网格。
  - 构造线从门框各边延伸到画面外。
  - 尺寸标注「≤ 300 行 / 文件」「单一职责 · 先理解再修改」（这是 skill 里的硬约束）。
  - 右侧架构树 `src/ → ui/ api/ store/ utils/` 按八分音符生长。
- **为什么**：从「草稿」到「设计图」，对应「架构设计」阶段。

### Phase 3 · 扁平（12–14s）

- **画面**：
  - 11.84–12.0s 闸门从下往上灌满朱红 `#FF5A36`。
  - 12.0s 圆形转场（iris）从门中心扩张，露出藏青色 `#1F2A44` 的瑞士海报世界。
  - 包豪斯几何装饰（黄圆、蓝半圆、奶白三角、薄荷环、朱红条）弹出。
  - 4 张任务卡「01 搭建表单组件 / 02 校验输入 / 03 对接登录接口 / 04 保存会话」每拍滑入一张。
- **为什么**：P2 的墨蓝「溢出」成为 P3 的背景色，颜色是连续的；任务卡对应「任务拆解」。

### Phase 4 · 等距黏土（14–16s）

- **画面**：
  - 镜头 0.5 秒内从正面转到等距视角（方位角 0° → -38°，仰角 0° → 27°，缓动 outExpo）。
  - 扁平图形「长出厚度」：深度从 0.015 倍长到 1 倍。
  - 灯光亮起，自发光的扁平色转成受光的黏土材质，有柔和阴影。
  - 琥珀色令牌按拍跳到每张卡上执行，卡片弹一下并出现对勾。
  - 一圈带箭头的循环环绕着卡片旋转（↻ 单步循环）。
- **为什么**：这是全片最「字面」的升维，2D 真的变成了 3D。观众亲眼看到同一个画面倾斜出第三个维度。

### Phase 5 · 写实（16–18s）

- **画面**：
  - 希区柯克变焦：视角 0.6° → 38°，同时保持目标平面的取景高度不变，背景的透视关系在剧烈变化。
  - 环境从黄昏黏土变成深夜：背景 `#04060B`，镜面反射地板，网格线，漂浮尘埃。
  - 闸门变钛金属（metalness 1，roughness 0.26），内外边缘的琥珀霓虹灯管像日光灯启动一样闪烁几下再亮稳。
  - 门洞里出现旋涡传送门（着色器）；任务卡变成青色描边的玻璃，对勾发绿光。
  - 17.0–18.0s 军鼓滚奏、镜头推进传送门、侧倾 6°、色差增大、辉光加强。
- **为什么**：「审查收尾」= 成品落地 = 最精致的质感。

### Act V · 静默（18–19s）

- **画面**：全黑。终端里依次出现：
  - 「✓ Phase 5 · 审查收尾 已完成」
  - 「是否确认交付？（确认 / 修改）」
  - 「❯ 确认」（人类打字，光标闪烁）

  18.75s 按下 ↵，文字像老式 CRT 关机一样压成一条线再收成一个点。同时上下遮幅（letterbox）收进来。
- **为什么**：全片唯一的真空（-26 dB）。留白是最重要的节拍，没有这一秒，drop 就不燃。

### Act VI · Drop（19–27s）

- **19.0s**：白闪爆发，视角从 40° 瞬间拉到 72°，冲进由 5 道 Gate 组成的蜿蜒隧道。
- **19.5、20.0、20.5、21.0、21.5s**：每拍穿过一道门，左下角弹出「01 需求分析 ✓」等标签。四周是 700 条光速拉丝。
- **21.5–22.0s**：穿过第 5 道门后减速慢放。
- **22.0s**：甩镜拉远（0.8 秒，inOutExpo），看到整条状态机：5 道门、发光的地面光路、第 4 道门外的循环环、每道门上方漂浮的对勾。
- **23、24、25s**：STOP. / CONFIRM. / SHIP. 三记砸字，下面是「停下 / 确认 / 交付」。
- **26–27s**：8 个 1/16 音符（每个 0.125s）闪切回顾：书桌、混乱、手绘 Gate、蓝图、扁平、黏土、写实、隧道。「STOP. CONFIRM. SHIP.」一整行定格在中间。

### Act VII · 片尾（27–30s）

- 背景的 3D 世界虚焦（blur 9px，亮度降到 45%）并继续缓慢环绕。
- 手绘 Π 形 logo 一笔画出。
- 标题「AI Phased Development Protocol」逐字母上浮去模糊，下面是手绘琥珀色下划线（每秒沸腾 12 次）。
- 然后依次出现 slogan「让 AI 每一步，都等你点头。」、仓库地址、「PHASE-GATE SKILL · CURSOR · WINDSURF · ANTIGRAVITY」。
- 29.45–29.95s 淡出。
- **为什么**：手绘线条和钢琴回来，从「燃」落回「暖」，结构闭环。

## 3. 节奏、剪辑、音画配合的专业技巧

### 3.1 节奏技巧

| 技巧 | 具体做法 | 为什么有效 |
|---|---|---|
| 单一节拍网格 | 所有时间点写在 `src/timeline.js`，120 BPM | 画面、文字、音乐都引用同一个数，不会漂移 |
| 固定小节模式 | 每个 Phase 一小节：第 1 拍转场重击，第 2–3 拍内容弹出，第 4 拍「确认叮」加进度点亮 | 重复的结构让观众形成预期（「下一拍一定升维」），预期被一次次满足就是节奏感 |
| 密度递增 | 代码飞出时间 `s_i = 4.25 + 3.45·√(i/70)`（开平方，越来越密）；弹出从四分音符到八分再到十六分；蒙太奇 1/16 | 能量靠事件密度堆起来，不靠音量 |
| 留白 | 砸门后冻结 0.2s；drop 前 1s 真空 | 对比产生冲击 |
| 预备动作 | 闸门先慢垂 0.3s 再在 0.1s 内猛砸；军鼓滚奏八分 → 十六分 → 三十二分 | 身体先于画面预感到冲击 |
| 确认铃逐级升高 | A5 → C6 → D6 → E6 → G6 | 听觉上的「升维」 |

### 3.2 剪辑手法（全部是代码实现的）

| 手法 | 用在哪 | 实现 |
|---|---|---|
| 硬切推近（smash cut） | 5.0 / 5.5 / 6.0 / 6.5 / 7.0s | 分段相机，段与段之间不插值，直接跳到批注位置，缩放 1.55–1.76，旋转 ±1.5–3° |
| 变速（speed ramp） | 闸门下落；第 5 道门后 | 分段缓动：outCubic 缓降，再 inQuad 猛砸；相机参数按 outCubic 减速 |
| 冲击帧 | 8.0s 反色 2 帧；23/24/25s 反色 1 帧 | 给整个舞台设 CSS `filter: invert(1)` |
| 白闪 | 所有重击 | fx 画布铺白色，透明度按 `exp(-(t-h)*k)` 衰减 |
| 衰减震屏 | 所有重击 | `shake(t,t0,amp,decay,freq)`：噪声位移乘以指数衰减 |
| 冻结后坠落 | 砸门后 | 混乱元素按 `min(t, 7.99)` 取状态，8.2s 后加 `y += 2600·f²` |
| 圆形转场（iris） | 12.0s | 给 SVG 层设 CSS `clip-path: path(evenodd, 全屏矩形 + 扩张的圆)` |
| 变形转场 | 手绘 → 矢量；扁平 → 3D；黏土 → 写实 | 同一个物体换参数，不是两个镜头切换 |
| 希区柯克变焦 | 16.0–16.7s | 视角增大的同时按 `d = frameH/2 / tan(fov/2)` 缩短距离 |
| 甩镜揭示 | 22.0s | 位置和看向点按 inOutExpo 从隧道出口插值到环绕位 |
| 动态文字 | STOP / CONFIRM / SHIP | 缩放 1.5 → 1、模糊 14px → 0（0.14s，outExpo），加红青色差 text-shadow 按 `exp(-12t)` 衰减 |
| 遮幅 | 18–27s | fx 画布上下画黑条，高 74px |
| 闪回蒙太奇 | 26–27s | 时间映射：`sceneTime(t)` 把这 1 秒映射回 8 个历史时刻（见 2.2） |
| 虚焦 | 片尾 | 给 GL 画布设 CSS `blur(9px) brightness(.45)` |

### 3.3 缓动规则（全片统一）

| 用途 | 缓动 |
|---|---|
| 冲击、到位 | outExpo |
| 弹出、吸附、抬杆 | outBack（s = 1.4–2.5） |
| 砸下、加速进入 | inQuad / inExpo / inQuart |
| 运镜 | inOutCubic |
| 淡出 | inQuad |

按功能固定选哪种缓动，全片动作的手感才一致。

### 3.4 音画同源

配乐不是做完画面再去对的，而是用同一条时间轴合成的：

- 铅笔沙沙声：Python **直接解析 `paper.js` 源码**里每一笔的 `t0 / dur`，画一笔响一声。
- 故障点击音：用和画面同一个公式算出 70 行代码的飞出时间。
- 每个视觉事件都有声音：砸门（低频冲击、金属声、镲）、确认（铃）、卡片（呼啸声、落位声）、霓虹（电流嗡声）、回车（按键声、反向吸气音）、穿门（从右到左的声像呼啸）。
- 编曲跟着升维叠层：P2 只有底鼓和拨弦 → P3 加拍手 → P4 加踩镲 → P5 加锯齿和弦与滚奏。拨弦的滤波器截止频率逐段打开（1600 → 2600 → 3800 → 6000 Hz），耳朵听到「变亮」和眼睛看到「升维」同步。

# 二、具体的创作方式

## 1. 技术栈与完整工作流

### 1.1 技术栈

| 层 | 选型 | 版本或备注 |
|---|---|---|
| 2D 手绘世界 | 原生 SVG + 自写手绘笔触引擎（`sketch.js`） | 没有用 rough.js |
| 3D 世界 | Three.js | 0.169.0：EffectComposer、UnrealBloomPass、ShaderPass、OutputPass、RoomEnvironment、Reflector |
| 文字层 | HTML + CSS（每帧重建 innerHTML） | |
| 后期层 | Canvas 2D（颗粒、遮幅、白闪） | |
| 字体 | 霞鹜文楷 `lxgw-wenkai-webfont`、`@fontsource` 的 Caveat / JetBrains Mono / Space Grotesk / Noto Sans SC | 全部走 npm，离线可用 |
| 逐帧渲染 | Playwright（Chromium headless）+ CDP `Page.captureScreenshot` | playwright 1.56 |
| 编码 | ffmpeg（libx264 + AAC） | 用 `pip install imageio-ffmpeg` 获取带 x264 的二进制 |
| 配乐 | Python 3 + numpy + scipy（`signal.butter`、`sosfilt`、`fftconvolve`） | 纯合成，无采样 |
| 检查工具 | PIL 拼接触表；matplotlib 画 RMS 和频谱图 | |

### 1.2 完整工作流（这次的真实顺序）

### 2.2 核心代码 1：时间轴是唯一的时间来源

```js
// src/timeline.js
export const T = {
  chaos: 4.0, slam: 8.0, confirm1: 9.5, p2: 10.0, p3: 12.0, p4: 14.0, p5: 16.0,
  black: 18.0, enter: 18.75, drop: 19.0, reveal: 22.0, words: 23.0, montage: 26.0, title: 27.0, end: 30.0,
};
export const CONFIRMS = [9.5, 11.5, 13.5, 15.5, 17.5];   // 每个 Phase 最后一拍

// 26–27s：8 个 1/16 音符闪切回之前的时刻
export const MONTAGE = [2.6, 6.55, 9.2, 11.4, 13.4, 15.35, 17.2, 24.4];
export function sceneTime(t) {
  if (t >= T.montage && t < T.title) {
    const i = Math.min(7, Math.floor((t - T.montage) / 0.125));
    return MONTAGE[i] + ((t - T.montage) % 0.125);
  }
  return t;
}
```

### 2.3 核心代码 2：每一帧都是时间的纯函数

```js
// src/main.js
export function render(t) {
  const st = sceneTime(t);        // 场景时间（蒙太奇会映射回过去）
  renderPaper(st);                // SVG 纸面层
  world.render(st, t);            // Three.js 层（st 决定内容，t 决定冲击特效）
  renderUI(st, t);                // 文字层
  renderFX(t, st, stage);         // 颗粒、遮幅、闪光
}
window.__render = render;         // 给 Playwright 调用
```

**铁律：** 任何模块都不能依赖上一帧的状态、`Date.now()` 或 `requestAnimationFrame` 的累计时间。所有随机数都用固定种子（`rng(seed)` / `hash()` / `noise1()`）。这样才能：

- 逐帧精确渲染；
- 多进程分段并行渲染；
- 蒙太奇直接复用过去的时刻；
- 预览时任意拖动。

## 3. 每种视觉风格的代码实现

| 风格 | 时间 | 技术 | 关键实现 |
|---|---|---|---|
| 手绘铅笔 + 水彩 | 0–10s | SVG | 见下文 |
| 蓝图矢量 | 10–12s | SVG | 见下文 |
| 扁平瑞士海报 | 12–14s | Three.js（伪正交） | 见下文 |
| 等距黏土 | 14–16s | Three.js | 见下文 |
| 写实科技 | 16–27s | Three.js + 后期 | 见下文 |

**手绘铅笔 + 水彩（0–10s）**

- **纸张**：启动时用 Canvas 生成 2240×1360 的纸纹（低频斑驳 + 颗粒 + 900 根纤维 + 暗角），导出成 JPEG dataURL，作为 SVG `<image>`。纸比画面大 140px 余量，震屏时不会露边。
- **笔触**：`strokeD()` 生成填充多边形，12fps 沸腾。
- **石墨颗粒**：`<mask>` 里放 4 张 1024 的噪声图，只作用在笔触组上。
- **水彩**：`Wash` 类按多边形生成 3 层边缘不规则的 blob，透明度 0.55 / 0.3 / 0.3，最后一层带同色描边模拟边缘积色，`mix-blend-mode: multiply`，出场时缩放 0.9 → 1。
- **灯光**：启动时在 Canvas 上用 `ctx.filter='blur(26px)'` 预先画好光锥，存成图片（不要用实时 SVG 模糊滤镜，见坑 #2）。
- **手写字**：SVG `<text>` + 霞鹜文楷。逐字出现（`typed()` 按每秒字数截取），每个沸腾帧有 ±0.7px 抖动。
- **铅笔图标**：`Drawing.tip(t)` 返回最新一条正在画的笔画的尖端坐标，铅笔跟着走。

**蓝图矢量（10–12s）**

- 抖动幅度 `wob = 1 - outBack(k, 2.2)`，0.32s 内归零；归零后改用真正的 `<path stroke>`（锐利、线宽一致）。
- 纸面盖一层 `#FBFAF6`，透明度 0.92。
- 点阵：一条包含约 1300 个子路径的 path（`M x,y h1.6`）。
- 构造线透明度 0.22，尺寸线带箭头，等宽字 JetBrains Mono。

**扁平瑞士海报（12–14s）**

- 相机视角 0.6°，世界坐标与像素对齐，所以 3D 闸门和 SVG 闸门严丝合缝。
- 材质只用自发光 + `NoToneMapping`，保证颜色等于色值。
- 物体都是 `ExtrudeGeometry`（前表面放在 z=0，向后挤出），深度先缩成 0.015 倍。
- 卡片文字用 CanvasTexture（2 倍分辨率）。

**等距黏土（14–16s）**

- 相机转到等距视角。
- 深度缩放 0.015 → 1。
- 光照：HemisphereLight 1.25 + DirectionalLight 2.6（2048 阴影贴图，PCFSoft）。
- 地面 `#2B3558` 接收阴影。
- `ACESFilmicToneMapping`，材质粗糙度 0.72。

**写实科技（16–27s）**

- 金属：metalness 1、roughness 0.26、clearcoat 0.6，环境贴图用 RoomEnvironment（PMREM），`scene.environmentIntensity` 设为 0.35–0.4。
- 霓虹：`MeshBasicMaterial` 的 HDR 颜色（琥珀 × 2.6–3.2），`toneMapped: false`，交给辉光。
- 传送门：自写着色器，极坐标 + 5 层 fbm 旋涡，琥珀 → 青色，加法混合。
- 地面：`Reflector` 做真实镜面（960×540 反射贴图）+ 上面盖一层 `MeshBasicMaterial` 黑色、透明度 0.8。
- 辉光：`UnrealBloomPass`，强度 0.5–0.6、阈值 0.9、半径 0.32–0.42。
- 最终着色器：色差 + 暗角 + 颗粒 + 白闪 + 数值钳制 `clamp(c, 0, 64)`。
- 隧道：CatmullRom 曲线（centripetal）穿过 5 道门；门按曲线切线朝向，放大 1.5 倍，y 偏移 +120 让门脚落地；700 根 InstancedMesh 细长方块做光速拉丝；1600 颗 Points 尘埃。

**文字层（ui.js）**

- 每个时代一套 HUD：
  - P1：手写体 + 手绘琥珀下划线；
  - P2：等宽字 + 细横线；
  - P3/P4：150px 的 Space Grotesk 数字 + 思源黑体 Black；
  - P5：`[ PHASE 05 ] ● LIVE` 霓虹风。
- 每次切换用 `clip-path: inset(0 X% 0 0)` 在 0.28s 内从左划出。
- 底部 5 个进度点也跟着时代换样式：手绘圈 → 描边圆 → 实心圆 → 带投影 → 发光。

## 4. 音频处理

### 4.1 规格

48000 Hz、立体声、30.0 秒，输出 `audio/score.wav`（16-bit）。混进视频时编码为 AAC 256k。

### 4.2 乐器（全部用 numpy 合成）

| 名称 | 做法 |
|---|---|
| 毛毡钢琴 `piano()` | 9 个带轻微非谐性的分音（`fk = f·k·√(1+0.0004k²)`），高次分音衰减更快；加 10ms 的琴槌噪声；低通 1800–5300 Hz |
| 拨弦 `pluck()` | 24 个谐波，按 `exp(-t·(6+1.8k))` 衰减 |
| 超级锯齿 `supersaw()` | 每个音 7 个失谐锯齿波（±1.2%），立体声铺开，4 阶低通 |
| 底鼓 `kick()` | 正弦波，频率从 156 Hz 按 35ms 时间常数降到 46 Hz；叠加 4ms 的咔嗒声；tanh 饱和 |
| 拍手 / 军鼓 / 镲 / 吊镲 | 滤波白噪声加包络；拍手是 3 个间隔 9ms 的噪声脉冲 |
| 冲击 `boom()` | 正弦频率下扫 + 低通噪声 + tanh 失真 |
| 金属声 `clang()` | 5 个非谐分音（523 / 1291 / 1877 / 2744 / 3651 Hz） |
| 铃 `bell()` | 分音比例 1 / 2 / 2.76 / 5.4 / 8.93 |
| 呼啸 `whoosh()`、升调 `riser()` | 逐样本的一阶低通，截止频率随时间扫动；声像从左扫到右 |
| 铅笔 `scratch()` | 1.8–7.5 kHz 带通噪声 × 35 Hz 低通噪声做颗粒调制 |
| 黑胶噪声 `crackle()` | 稀疏脉冲 + 低频底噪 |
| 混响 | 2.6 秒合成立体声脉冲响应（指数衰减 τ=0.55 的低通噪声），`fftconvolve`，用 send 总线 |

### 4.3 和声与旋律

- **Act I**：Fmaj7（0–2s）→ Dm9（2–4s）琶音，加动机 A4 C5 E5 F5 E5 D5。
- **Act II**：Bb 加 #11 的紧张和弦断奏，节奏从 1/4 加速到 1/8 再到 1/16；6 秒后加入 C#5 不协和音。
- **升维段和 drop**：Dm – Bb – F – C（i – VI – III – VII），每个和弦 2 秒。
- **drop**：19s 和 23s 各重复一次动机，用锯齿波 + 高八度钢琴。
- **片尾**：Fmaj7 琶音 + 动机前 3 个音，放慢到 1.4 倍时值。

### 4.4 卡点与混音处理

1. **侧链压缩**：10–26 秒，每个底鼓之后整体压低 35%，按 `exp(-since/0.09)` 恢复，做出「泵感」。
2. **静默门**：18–19 秒整轨压到 6%，然后把按键声、回车声、反向吸气音单独干净地叠回去。
3. **蒙太奇切片**：把 25.0–25.125 秒已混好的音频切下来，在 26–27 秒重复 8 次（每次 0.125 秒减 10ms），加咔嗒声和升调。
4. **分段增益自动化**（第一版动态太平，这是修复手段）：

```python
auto = np.interp(t, [0, 3.9, 4.0, 7.9, 8.0, 8.5, 9.4, 10.0, 15.9, 16.0, 17.9, 19.0, 25.9, 26.0, 27.0, 30.0],
                    [0.42, 0.45, 0.5, 0.85, 1.0, 0.75, 0.55, 0.72, 0.85, 0.92, 1.0, 1.0, 1.0, 0.8, 0.95, 0.9])
```

5. **母带**：28 Hz 高通 → `tanh(x·1.1)` 软削波 → 峰值归一化到 0.89 → 最后 0.5 秒平方曲线淡出。

## 6. 时间分配与提速

### 6.1 这次的时间分配（按工作量估计）

| 环节 | 占比 | 备注 |
|---|---|---|
| 需求对话 + 创意和分镜 | 约 10% | 3 轮对话 |
| 环境与管线（服务器、渲染器、编码器） | 约 5% | |
| 手绘引擎 + 2D 纸面世界 | 约 25% | 最多细节 |
| 3D 世界（三个时代 + 隧道） | 约 25% | 坑最多（NaN、发灰、太小） |
| 文字层 + 后期层 | 约 8% | |
| 配乐合成 + 响度验证 | 约 10% | |
| 静帧迭代与排错 | 贯穿全程，约 15% | 每轮出 4–12 张静帧约 10–60 秒 |
| **成片渲染（机器时间）** | **最长的一段** | 30fps 预览 900 帧：18:03 → 18:22，约 19 分钟 |

### 6.2 实测渲染速度（云端：4 核、无 GPU、SwiftShader）

| 配置 | 速度 |
|---|---|
| 单帧静帧（热启动） | 2D 段 0.7–3.6 s/帧；3D 段 1.6–2.4 s/帧；首帧因为着色器编译要 5–6 s |
| 4 个进程 60fps | 每进程 14–18 s/帧，负载 14，预计超过 2 小时 → 中止 |
| 2 个进程 30fps | 2D 段 1.4–1.9 s/帧，3D 段 2.6–3.3 s/帧 → 900 帧约 19 分钟 |

### 6.3 提速方法（优先级从高到低）

1. **本地用 GPU 渲染**（`--gpu`）。这是最大的提速手段，这次成片就是用户在本地渲的。
2. **进程数不超过核心数的一半**。SwiftShader 和 Chromium 本身就是多线程的，4 核机器开 4 个进程反而更慢。
3. **迭代阶段只出静帧，不出视频**：每轮 4–12 张，拼成接触表一次看完。
4. **先出 30fps 预览**，确认后再出 60fps。
5. **去掉昂贵的绘制**：全屏 SVG 遮罩、实时 SVG 模糊滤镜、大面积 `mix-blend-mode`。
6. **捕获用 CDP `optimizeForSpeed`**。「连拍两次一致」的检查会多一次捕获（约 0.2–0.3 s）；确认画面稳定后可以关掉。
7. 用 `deviceScaleFactor 0.5` 做半分辨率预览**没有效果**：绘制是瓶颈，截图仍然是 1920 宽。不要在这上面浪费时间。

## 2. 踩坑实录

> 格式：**现象** → **根因** → **解决** → **下次怎么提前避免**

### 渲染与导出

**#1 预览控制条出现在渲染画面里**
- 现象：第一批静帧底部有播放按钮和时间轴。
- 根因：`<div id="controls" hidden>` 的 `hidden` 属性被 CSS 里的 `#controls { display: flex }` 覆盖了。
- 解决：加一条 `#controls[hidden] { display: none; }`。
- 下次：只给预览用的 UI 默认不渲染，或者给 `[hidden]` 写全局规则。

**#2 画面上出现大块米色矩形（缺块）**
- 现象：5.2s 左下角一大块米色矩形盖住台灯；10.2s 大半个画面空白，边界是整齐的瓦片边缘。
- 根因：包住整个相机组的全屏 SVG 遮罩（`<mask id="iris">`）让 Chromium 需要超大的离屏表面，超出了光栅瓦片预算，部分瓦片根本没画。**不是时序问题**：连截两次结果一模一样。
- 走过的弯路：加 `--run-all-compositor-stages-before-draw`、等两个动画帧、「连拍直到一致」，都没修好。
- 解决：去掉 SVG 遮罩，圆形转场改用 CSS `clip-path: path(evenodd, ...)`，只在转场那 0.3 秒内设置；灯光的实时 SVG 模糊滤镜改成启动时在 Canvas 上预先模糊好的图片。
- 下次：**SVG 里不要用全屏的 mask 或 filter**；这类效果用 CSS clip-path、预渲染图片或 Canvas。用 `probe.mjs` 逐个移除属性，能很快定位。

**#3 静帧很慢（每张约 1–1.5 秒）**
- 现象：JS 计算只要 4–9ms，截图却要 1.1–1.6 秒。
- 根因：Chromium 的绘制（光栅化）是瓶颈：石墨颗粒遮罩、模糊滤镜、正片叠底各占约 0.7 秒，内容本身约 0.37 秒，截图的固定开销约 0.14–0.3 秒。
- 解决：改用 CDP `Page.captureScreenshot` 加 `optimizeForSpeed`；去掉全屏遮罩和滤镜；接受剩下的开销，靠并行和 GPU 弥补。
- 下次：先写性能探针（分别计时 JS、等待帧、截图、再截一次），再决定优化什么。

**#4 并行进程开太多反而更慢**
- 现象：4 核机器开 4 个进程，每进程 14–18 s/帧，负载 14，预计超过 2 小时。
- 根因：每个 Chromium 加 SwiftShader 自己就是多线程，4 个进程严重争抢 CPU。
- 解决：中止，改为 2 个进程 + 30fps，19 分钟出预览；60fps 成片交给用户本地用 GPU 渲染。
- 下次：进程数不超过核心数的一半；先用 60 帧试跑测速度，再决定开几个。

**#5 半分辨率预览没有提速**
- 现象：`deviceScaleFactor 0.5` 加 WebGL 半分辨率之后，截图仍是 1920×1080，每帧 0.7–2.7 秒。
- 根因：绘制才是瓶颈，而且 CDP 截图还是按 CSS 像素出图。
- 下次：预览提速靠降帧率、减进程争抢、用 GPU，不靠降分辨率。

**#6 用 `pkill -f` 把自己的 shell 杀了**
- 现象：执行 `pkill -f "render/render.mjs"; ...` 之后整条命令返回 144，后面的修改都没执行。
- 根因：当前 bash 命令行里本身就含有这个字符串，`pkill -f` 也匹配到了自己。
- 解决：记下进程号，用 `kill PID`；或者单独执行 pkill，不和别的命令串在一起。
- 下次：后台任务启动时就把进程号写到文件里。

**#7 进度监控重复**
- 现象：中止重开渲染后，旧的监控还在盯同一个日志，同一条进度收到两次。
- 解决：重开任务前先停掉旧监控。
- 下次：每次重启后台任务都顺手清理旧监控。

**#8 首帧耗时导致预计时间严重失真**
- 现象：第一条日志显示 6.6–18 s/帧。
- 根因：首帧包含着色器编译和页面预热。
- 下次：从第 60 帧的速度开始估算。

### 帧率与时长

**#9 时间必须由帧号算出**
- 做法：第 f 帧的时间 = f / FPS。分段渲染时每段的起止帧用 `Math.round(from*FPS)` 计算，拼接用 concat demuxer 加 `-c:v copy`。30fps 预览实测时长 00:00:30.00。
- 下次：不要用任何实时时钟驱动动画。

### 音频与画面同步

**#10 合成音频时数组长度差 1**
- 现象：`ValueError: operands could not be broadcast together with shapes (98399,) (98400,)`。
- 根因：`int(sec*SR)` 在浮点误差下少 1 个样本，和 `int(round(...))` 算出的长度不一致。
- 解决：全部统一成 `int(round(x * SR))`。
- 下次：音频合成里所有「秒 → 样本数」的转换只写一个函数。

**#11 配乐动态太平**
- 现象：温馨段 -13.6 dB，几乎和 drop（-8.2）一样响；砸门之后的握手段还有 -9.9 dB（冲击声的尾巴太长）。
- 根因：峰值归一化会把所有段拉到接近的响度；铅笔声和黑胶噪声太响；冲击声持续 2.4 秒、混响送得多。
- 解决：分段增益自动化；黑胶噪声 0.02 → 0.008；铅笔声 0.05 → 0.03；冲击声 2.4s → 1.5s，混响送出 0.5 → 0.3；蒙太奇切片的增益 0.6 → 0.35。
- 下次：**写完配乐第一件事是逐段测 RMS**，对照情绪曲线（目标：温馨约 -20、drop 约 -8、静默低于 -25）。

**#12 音画同步的做法**
- 所有音效的时间点都从 `timeline.js` 的同一组数、同一个公式，甚至直接从 `paper.js` 源码里解析出来。合成时 `place()` 按 `round(t*48000)` 放置。混进视频时用 `-ss from -t (to-from)`，所以切片渲染也同步。
- 下次：改了画面时间点就重新跑 `npm run music`。最好把解析范围从 buildDesk 扩大到所有场景，做到完全自动。

### BGM 与音效卡点

**#13 静默段必须真的静音**
- 做法：18–19 秒把整轨压到 6%，按键声、回车声、吸气音单独叠加在门之后。否则前面冲击声和混响的尾巴会渗进来，真空感就没了。

**#14 蒙太奇切片的音量叠加**
- 现象：26–27 秒 -5.6 dB，比 drop 还响。
- 根因：切下来的音频叠加在还在延续的 C 和弦上面。
- 解决：切片增益降低，加上自动化曲线在 26 秒处降到 0.8。

### 中文字体与文字排版

**#15 英文字体没加载（回退成衬线体）**
- 现象：8.1s 的 "GATE 1" 显示成宋体风格的衬线字，9.3s 又正常了。
- 根因：fontsource 和霞鹜文楷都按 Unicode 分片。预加载时用的样本字符串是「确认」（纯中文），Caveat 只有拉丁分片，没有被触发加载。
- 解决：样本字符串改成 `'确认 GATE Phase 0123456789 abcxyz'`；启动时把全片每 0.25 秒渲染一遍，触发所有分片下载，再等 `document.fonts.ready`。
- 下次：预热渲染全片 + 预加载时覆盖中英数三类字符，两步都做。

**#16 Canvas 贴图里的字体**
- 做法：Three.js 的卡片文字是 Canvas 画的；画之前必须 `document.fonts.load(font, 实际字符串)`，否则贴图里是回退字体，而且之后不会自动更新。

**#17 字被背景吃掉**
- 现象：
  - 混乱段的主角代码和红批注被其他代码行压着，看不清；
  - 蒙太奇的白色大字压在浅色纸面上，几乎看不见。
- 解决：
  - 主角行和批注最后画，用 `stroke="#F2E8D6" stroke-width="10–12" paint-order="stroke"` 做纸色描边；
  - 蒙太奇加一条半透明深色渐变底衬（`rgba(4,6,12,.72)`）。
- 下次：大字压在变化的背景上时，一律带描边、阴影或底衬。

**#18 元素重叠和信息重复**
- 现象：P3 左上角 HUD「03 任务拆解」和黄色圆形打架；P1 左上 HUD「Phase 1 需求分析」和需求清单标题「需求 · Phase 1」重复。
- 解决：圆形从 (-400, 250) 挪到 (-330, 110)；清单标题改成「需求清单」。
- 下次：HUD 占用的区域要事先留出来，装饰元素避开。

**#19 确认提示字太小**
- 现象：18.5s 全黑画面中间只有很小的 30px 等宽字，这个「灵魂时刻」没有分量。
- 解决：字号 30 → 40，提示行 40 → 64。

### 不同风格和场景之间的衔接

**#20 2D 和 3D 如何无缝交接**
- 做法：Phase 3 的扁平画面其实已经是 Three.js 场景，用 0.6° 视角、取景高度 1080 让世界坐标严格等于像素坐标（x-960, 540-y），闸门几何和 SVG 一模一样。
- 细节：挤出模型的倒角（bevel 3）会把外轮廓撑大 3px，所以 Π 形状要预先向内缩 3px。
- 交接帧：SVG 里先从下往上把门灌满朱红，然后 CSS 圆形遮罩打开，露出下面的 GL 层。

**#21 闸门下落看不见**
- 现象：7.9s 的静帧里完全没有闸门。
- 根因：用了 inExpo（`2^(10k-10)`），门在画面外一直待到最后两帧，观众看不到「砸下来」的过程。
- 解决：两段式：7.6–7.9s 从 -1150 缓降到 -760（露出门脚，制造压迫感），7.9–8.0s 用 inQuad 猛砸。
- 下次：变速镜头要保证物体在画面里至少停留 10–20 帧。

**#22 震屏时画面转了 40–70°**
- 现象：7.95s 画面几乎转了 45 度。
- 根因：`shake()` 返回的旋转分量已经是 `amp*0.02`，又乘了 57（弧度转角度），amp=34 时变成 39°；另一处手动震动写成了 `k*0.08`。
- 解决：旋转系数改成 `amp*0.0008` 和 `k*0.0015`，震屏旋转控制在 ±1–2°。
- 下次：震屏的旋转上限写成常量（例如 ±2°），加断言。

**#23 画面乱涂显得机械**
- 现象：用 `hatch()` 做的混乱段排线是一块块整齐的矩形之字形，像机器画的。
- 解决：改成 `scribble()`：沿随机游走路径叠加半径 40–110 的旋转圆圈，就是「愤怒的圈圈乱涂」。
- 下次：有机效果用「路径 + 旋转」生成，不用规则网格。

**#24 水彩形状太方**
- 现象：月亮和植物的晕染是方形或菱形色块。
- 解决：月亮用 `arc()` 的圆形多边形，植物直接复用叶片的样条轮廓。
- 下次：晕染多边形从线稿本身派生。

**#25 写实段出现黑色巨块（NaN）**
- 现象：16.3s 画面中间有一个巨大的纯黑矩形。
- 排查：隐藏 studio 组，黑块消失；逐个隐藏子物体并 `readPixels` 读中心像素，定位到是闸门；关掉雾、改灰背景，黑块依然存在。
- 根因：传送门补光 `PointLight(intensity 5e5, decay 1.2)` 离金属门太近，镜面项让半精度浮点溢出成 Inf/NaN。UnrealBloom 的模糊把 NaN 扩散成一大片（即使辉光强度为 0，NaN × 0 仍然是 NaN）。
- 解决：光强改成 1.6e5、decay 2；最终着色器加 `c = clamp(c, 0., 64.)`。
- 下次：HDR 管线里的强光要按物理衰减（decay 2）估算；最终着色器必须钳制数值。

**#26 写实段一片白雾**
- 现象：16.9–17.9s 大面积泛白。
- 解决：
  - 辉光强度 0.95 → 0.6，阈值 0.82 → 0.9，半径 0.6 → 0.42（隧道里 0.32）；
  - 霓虹灯管亮度 5 → 3.2，卡片描边 2.6 → 1.8；
  - drop 白闪的衰减速度 7 → 12；
  - 隧道里门的亮度 `4+6·near` → `2.6+2.5·near`。
- 下次：辉光从小往大调，阈值不低于 0.85；每次调完都看最亮的那一帧。

**#27 地板发灰**
- 现象：隧道和揭示段的地面整片发灰，看不出是镜面。
- 排查：逐个隐藏反射面、黑色地面、网格和尘埃，隐藏黑色地面后地板就变黑了。
- 根因：半透明的 `MeshStandardMaterial` 地板（粗糙度 0.35）吃到方向光的高光。
- 解决：改成 `MeshBasicMaterial({ color: '#020306', opacity: 0.8 })` 盖在反射面上。
- 下次：夜景地面用不受光的材质盖在反射面上，最干净。

**#28 金属发白**
- 根因：RoomEnvironment 是明亮的室内环境，在夜景里把金属照成了白色。
- 解决：`scene.environmentIntensity` 在写实段设为 0.4，隧道设为 0.35。

**#29 揭示镜头里门太小、而且是侧面**
- 现象：22–29s 的门远看像细长的板子，读不出 Π 形。
- 解决：
  - 隧道门放大 1.5 倍，y 偏移 +120 保持门脚落地；
  - 相机从侧面环绕改成 3/4 前侧俯视：θ 0.22 → 0.8，半径 4300 → 5200，高度 1250；
  - 看向点改成 (0, -240, -2700)。

**#30 NoToneMapping 和辉光的配合**
- 扁平段的颜色必须严格等于设计色值，所以只用自发光加 `NoToneMapping`。
- EffectComposer 下色调映射在 OutputPass 里做，切换 `renderer.toneMapping` 不会触发材质重新编译。
- 切换点放在 14.0s 的冲击帧和快速运镜里，观众看不出跳变。

### 文件体积与下载限制

**#31 预览版 465 MB**
- 现象：30fps、30 秒的预览有 465 MB，码率 124 Mbps。
- 根因：CRF 14 是母版级质量，而且每帧都在变化的颗粒噪点几乎无法压缩。
- 解决：母版和分享版分开；分享版用 `-b:v 12M -maxrate 16M`（约 45 MB，这次未实测）。
- 下次：成片的编码参数一开始就分两档；颗粒强度不要超过 0.03。

**#32 仓库单文件 100 MB 上限**
- 解决：`promo/out/` 和 `promo/audio/score.wav` 加进 `.gitignore`；视频不进仓库，配乐可以一条命令重新生成。
- 下次：项目一开始就把渲染产物加进忽略列表。

### 运行环境与依赖

**#33 Playwright 自带的 ffmpeg 没有 libx264**
- 现象：`/opt/pw-browsers/ffmpeg-1011` 只能编 VP8。
- 解决：`pip install imageio-ffmpeg`，调用 `imageio_ffmpeg.get_ffmpeg_exe()`，自带 x264 和 AAC。
- 下次：开工时就执行 `ffmpeg -encoders | grep 264` 确认。

**#34 渲染脚本写死了云端路径**
- 现象：`require('/opt/node22/lib/node_modules/playwright')` 和 `python3` 在用户电脑上都不存在。
- 解决：
  - 先找项目自己的 playwright，找不到再用全局的；
  - ffmpeg 按 `$FFMPEG` → imageio-ffmpeg（依次试 python3 和 python）→ PATH 里的 ffmpeg 的顺序查找；
  - 加 `--gpu` 开关；
  - `package.json` 加 `devDependencies.playwright` 和 `render:gpu` 脚本。
- 下次：写完就假设「会在别人的 Windows 电脑上跑」，检查一遍路径、命令名和 GPU 开关。

**#35 ES module 不能用 file:// 加载**
- 解决：写一个以 `promo/` 为根目录的 `serve.mjs` 静态服务器，页面通过 `http://127.0.0.1:{port}/src/index.html` 访问；three 通过 import map 指向 `node_modules`。
